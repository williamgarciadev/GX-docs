# Blocked parameters property

Determines whether the generator will use structures to pass parameters between programs. If you set this option to Yes, parameters will be passed as a unique structure (blocked).

### [Values](#Values)

|  |  |
| --- | --- |
| **No** | Parameters will be passed and received individually (with no structure). |
| **Yes** | Parameters will be passed and received as a unique structure. |

### [Scope](#Scope)

**Generators:** Cobol  
**Level:** Generator

### [Description](#Description)

Default Value = No (to ensure compatibility with prior versions).

#### [[Notes:](https://wiki.genexus.com/commwiki/wiki?14021)](#https%3A%2F%2Fwiki.genexus.com%2Fcommwiki%2Fservlet%2Fwiki%3F14021%2CBlocked%2BParameters%2BProperty%23Notes%253A+Notes%3A)

Setting this option to Yes has some advantages:

* Reduces the execution time of the programs that make calls to other programs.
* Reduces the amount of resources involved in the call.
* Eliminates the 30-parameter limit for Cobol for iSeries.

And some disadvantages:

* The caller and called programs must be generated with the same value in this option; otherwise, errors will occur at execution time (not during compilation). Therefore, when working with existing applications, it’s strongly recommended to force the generation of all programs.
* External programs (not generated by GeneXus) referenced in CALL and SUBMIT commands should be modified in their parameter declaration section and compiled again.
* iSeries standard APIs (QCMDEXC, etc.) cannot be directly referenced in CALL or SUBMIT commands because they have not been designed to receive blocked parameters. The recommendation is to write programs (i.e. CLP) that receive the Blocked parameters and then call the corresponding API.
* Every time a call is made, a structure is internally generated containing one item for each parameter. This is generally irrelevant unless an entire matrix or array is passed as a parameter; in these cases, the array or matrix is duplicated in the above-mentioned structure, which may cause considerable iSeries memory consumption.

This option cannot be set to Yes if the application programs are going to be used as stored procedures.

A forced generation of all programs is recommended when this option value is modified.

The interface used is Windows.
