# GAM - Grouping of permissions

[GAM Permissions](https://wiki.genexus.com/commwiki/wiki?15912) can be grouped in hierarchies to ease their management.

Also, permissions can be defined using a hierarchical structure to make their maintenance easier.

In this hierarchy, there are children and parent permissions (it's a tree structure); as children inherit the behavior from their parent, any change in the parent is reflected in the children.

### [How do I define children permissions?](#How+do+I+define+children+permissions%3F)

Any permission ([Automatic Permissions generated by GeneXus](https://wiki.genexus.com/commwiki/wiki?17916) as well as [Permissions Created by the User](https://wiki.genexus.com/commwiki/wiki?18501,,)) can have children.

Permissions exist within the scope of [applications](https://wiki.genexus.com/commwiki/wiki?15910), so that's where Permission hierarchies are going to be defined.

To define a child for a permission, do the following:

* Execute the [GAM Backend](https://wiki.genexus.com/commwiki/wiki?15935)
* Go to WW Applications
* Edit the Permissions of the Application
* Find in the list the Permission that will be the "parent" Permission, and click on the icon shown in the figure below to define its children:

`[imagen omitida: wiki id 52564]`

###### [Figure 1. Given "Parent\_Permission" permission, you can add children by clicking on the image displayed.](#Figure+1.+Given+%22Parent_Permission%22+permission%2C+you+can+add+children+by+clicking+on+the+image+displayed.)

Next, click on the "Add Children" button and select the permissions that will be children of the parent permission.

`[imagen omitida: wiki id 52565]`

###### [Figure 2. Click on the Add Children button to select and add the children permissions](#Figure+2.+Click+on+the+Add+Children+button+to+select+and+add+the+children+permissions)

In this case, the children Permissions are: novels\_Execute, novels\_Updates, novels\_Insert.

Note that the Default [Permission Access Type](https://wiki.genexus.com/commwiki/wiki?20603) of the children will be the same as that of the parent. So, if you specify that the parent has "Restricted" Default Access Type, the same will apply for the children.

### [What happens when a "Parent" permission is associated with a Role?](#What+happens+when+a+%22Parent%22+permission+is+associated+with+a+Role%3F)

When a "parent" permission is associated with a [Role](https://wiki.genexus.com/commwiki/wiki?17569) all the children permissions of this "parent" are expanded in the list of permissions of the Role.

### [What changes can be done in a permission?](#What+changes+can+be+done+in+a+permission%3F)

In the Role, you can change the [Permission Access Type](https://wiki.genexus.com/commwiki/wiki?20603).  
If you change the Access Type of the "parent", their children take the changes, unless the inheritance has been lost.

The following figure shows how a change in the Access Type of "parent" permission impacts in its children.

`[imagen omitida: wiki id 52567]`

###### [Figure 5. Changes in Access Type of "parent" permission](#Figure+5.+Changes+in+Access+Type+of+%22parent%22+permission+)

### [When is inheritance lost?](#When+is+inheritance+lost%3F)

Inheritance is lost if the Access Type of a child is changed, or if the "Inherited" check box is changed.

For example, in the case above, if you change the Access Type of "novels\_insert", this permission loses inheritance from its parent, and it's reflected in the "Inherited" check box.

`[imagen omitida: wiki id 52568]`

###### [Figure 5. Permission loses inheritance](#Figure+5.+Permission+loses+inheritance)

Losing inheritance means that changes in the Access Type of the parent will not be reflected in the child.

**Note:** The real value of grouping permissions lies in the inheritance, so that the maintenance of several permissions is reduced to the maintenance of only one permission (the permission which "groups" the others). In fact, at execution time, the code checks for the children permissions, not the parent one, which is only a fictitious permission used to group the others.

### [Use Case](#Use+Case)

Suppose you have the following GeneXus code:

```
Event "Generate Payments"

 ProcA.call()
 .......... 
 ProcB.call()
 ............
 ProcC.call()

EndEvent
```

In this case, the permissions for executing ProcA, ProcB, and ProcC can be grouped in only one permission, so that the management of all these permissions is reduced to managing only one permission.
